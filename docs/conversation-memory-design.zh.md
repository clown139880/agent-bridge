# 中央对话检索、回顾与共享技能设计

日期：2026-09-18。状态：设计提案，尚未实现。

## 目标与边界

让 Codex、Claude、Hermes 和 DSH 在不同机器、不同原生会话中搜索和回顾已有讨论，继续思考，并将后续讨论再次归档。优先支持方案设计和研究，不要求迁移运行进程、未提交工作区或原生会话数据库。

职责分工：

| 内容 | 权威来源 |
| --- | --- |
| 项目当前实现、规范、设计与已落地决策 | 项目仓库中的代码、AGENTS.md、设计文档和 Git 历史 |
| 历史讨论、探索过程、未决问题及来源 | 中央对话服务 |
| 少量跨项目长期偏好 | 可选的中央有界记忆，不从历史建议自动提升为规则 |
| 可复用操作流程 | Git 管理的技能包 |

Obsidian 和 Syncthing 不作为必要依赖，可以后续提供笔记导出。项目无需保存 Agent Bridge 的 projectId。同一逻辑项目可以关联多个机器目录和多个仓库。

## 架构：Control Plane 统一提供 MCP

```text
Codex / Claude / Hermes / DSH
          │ 认证的远程 MCP
          ▼
Control Plane
  ├─ MCP：搜索、回顾、原文读取
  ├─ 项目与会话关联、权限、配额
  ├─ 对话归档、全文索引
  ├─ 摘要缓存与低优先级整理
  └─ 容量统计、归档与清理
          ▲
          │ 增量上报与离线补传
各端 Bridge / 来源适配器
  ├─ 会话采集
  ├─ 机器、工作目录和 Git 元数据
  └─ 共享技能安装与状态回报
```

各端 Bridge 不提供 MCP。查询不经过原会话所在机器：Windows 休眠后，HAL 上的客户端仍可直接访问中心已经收到的历史。中央服务不可用时第一版明确报告不可用，不承诺离线全库搜索。

MCP 采用远程 HTTP 接入；具体传输、认证和客户端配置在实施时验证兼容性。确实不支持远程 MCP 的客户端可用薄传输代理，不在每个 Bridge 重建 MCP 服务。MCP 必须配置到实际执行的 agent，DSH 的工具配置不会自动传给远端执行端。

第一版 MCP 只暴露读取能力。查询使用独立的只读身份，不复用 Bridge 注册密钥或控制操作的写权限。凭据通过客户端配置提供，不放进 prompt、技能或 Git。中心统一管理权限、撤销和查询限额；目录或 repository 参数只用于检索，不构成授权。

## 查询上下文和项目关联

对外接受关键词、cwd、machine_id、repository、项目别名、时间和来源 agent。中心内部可保留稳定项目 ID，不要求 agent 知道它。

远程 MCP 无法自行读取调用端文件系统，也不能假定工具调用包含可信的当前工作目录。上下文解析优先级：

1. 客户端显式提供的来源会话 ID，解析其已登记机器与工作目录。
2. 工具参数中的 machine_id + cwd，与 Bridge 已上报的映射匹配。
3. repository 或项目别名。
4. 缺少定位信息时使用关键词搜索，返回范围和候选，不猜测当前项目。

客户端若支持，可配置调用端身份或默认机器提示；不在一个共享 MCP 连接上存储唯一“当前项目”，以免并行会话串项目。调用端可用自身本地工具取得 cwd/Git 信息，再传入查询。

等价的 SSH/HTTPS Git remote 可以归一化，但仓库名称相同不代表同一项目。remote 中的凭据不得上报或索引。Fork、monorepo 子项目、多个 checkout 和无 Git 目录允许显式关联或拆分。分支为可选过滤条件，不默认隔断项目历史。

## MCP 工具契约

以下名称和参数为拟议契约：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| conversation_search | query、可选 cwd/machine_id/repository/source_session_id、scope、时间/agent 过滤、cursor、limit | 会话 ID、标题、时间、匹配原文片段、消息 ID、解析后的范围、下一页游标 |
| conversation_review | session_id、可选关注主题和输出预算 | 目标、约束、已确认决策、未接受建议、未决问题、近期消息、摘要覆盖范围、原文指针 |
| conversation_read | session_id、消息位置或 cursor、方向、limit | 原始消息、角色、时间、来源位置、前后页游标、完整度 |

搜索直接读取索引，不调用模型。回顾优先使用缓存摘要；缺少或落后时返回状态及预算内近期消息，允许后续后台整理。原文分页读取不改变正文，过长消息提供分段位置和明确截断标记，不悄悄省略。

所有结果包含适用的 source、collected_through、summary_through 和 completeness 信息。归档已过期时返回明确状态，不提供虚假的恢复指针。未来的 conversation_link 写能力单独设计和授权，不混入第一版只读接口。

## 采集、存储与摘要

查询和采集独立实现。Bridge 采集本机支持的执行端；Hermes/DSH 原生会话通过来源适配器增量导入，不让中央服务直接写其原生数据库。

来源键由来源实例、原生会话 ID、原生消息/事件 ID 组成。跨接口导入同一消息时维护来源别名；缺少原生 ID 的适配器使用稳定位置和来源版本设计去重，不只按文本去重。记录实际发生时间和采集时间，并保存增量游标。中心确认持久化后客户端才推进确认位置；重连可重放。端侧待传队列也有容量上限，超限必须报告采集缺口。

保存用户和助手最终消息、必要工具调用及状态；工具输出和附件按独立策略处理。当前 Bridge 事件投影的截断、保留窗口和 Desktop 历史缺口不能当成完整永久档案，接入时必须审计并标记。只归档来源实际暴露的数据。

摘要是可重建的导航层，不是原文替代品。每份摘要绑定消息范围、源内容版本、生成版本和时间，区分用户决定、助手建议和未决问题。重要路径、提交号和消息 ID 尽量机械提取，作为恢复锚点。来源发生编辑或删除时，使受影响摘要和索引失效或重建。

整理按新增内容阈值、空闲窗口或显式回顾需求触发，低优先级排队，设置并发和调用预算。摘要失败不阻断原文读取，也不删除原文。Bridge 不接管各 agent 自己的运行上下文压缩。

历史是资料，不提升为当前指令；项目现状以当前仓库为准。明确需要长期保留的个人偏好可另设小规模策展存储，第一版无需自动抽取全部个人记忆。

## 容量治理

### 先审计现状

统计各表与索引、SQLite WAL、附件、归档和备份占用；测量每日增长、最大会话、流式事件与最终消息重复程度，以及现有保留任务是否生效。在确认数据来源前不删除生产记录，首次清理先输出预览。

### 分层存储

| 类型 | 存储 | 策略 |
| --- | --- | --- |
| 会话元数据、来源映射、摘要 | SQLite | 长期保留，小体积 |
| 用户和助手最终消息 | 近期 DB；旧记录分块压缩归档 | 默认长期保留，容量策略显式配置 |
| 工具调用元数据和结果摘要 | DB/归档 | 随对话保留 |
| 大型工具日志、重复文件内容 | 压缩对象 | 较短保留期，支持明确保留 |
| 流式片段、重复进度、投递事件 | 事件表 | 满足可靠传输与恢复窗口后清理 |
| 图片、视频、附件 | 独立对象目录 | 独立配额和保留规则 |
| 全文索引 | 可重建派生数据 | 优先正文和必要工具摘要，限制大日志 |

第一版对象存储可以是 HAL 本地目录；所有数据、秘密和备份均在 Git checkout 外。不通过 Syncthing 同步活动 SQLite。

按会话和消息范围分块压缩，避免每条消息一个小文件。归档过程先写临时对象并校验，再原子发布对象、提交 DB 引用，确认可读取后才清除热存储副本；失败可重试并清理孤立对象。

冷归档压缩不会自动缩小全文索引。近期原文保持完整索引；历史可选择保留原文索引，或只索引摘要、标题和关键词。后一种模式必须明确报告搜索范围，因为它不能保证命中旧原文的任意字句。实施时根据实测体积选择，不承诺无限历史全文检索却忽略索引成本。中文搜索单独验收召回和空间放大比例。

使用数据类型保留期、总容量预算、对象大小限制、明确保留标记和清理审计共同控制增长。优先清理已过期运行事件和工具日志；压缩迁移历史正文。不得因空间不足静默删除正文或明确保留的会话。达到硬上限且无可清理内容时报告并暂停受影响归档，保留已有数据，明确新数据缺口。

删除策略覆盖正文、对象引用、索引、摘要和缓存；共享对象按引用回收。备份的删除延迟和保留期限需要明确。SQLite 数据清除后的空间回收在低峰执行，限制 WAL，预留归档临时空间。SQLite 备份使用在线备份机制，配合对象清单形成可恢复集合，并设置备份数量和容量上限。

## 技能交付

建议在本仓库增加 shared-skills/，由 Git 管理 conversation-recall、tokensapi-aigc 和 aigc-video-creation 等技能。conversation-recall 说明何时使用 MCP、如何解释摘要与历史，不承担 MCP 服务注册。

各端安装中央 MCP 配置与技能是两项配置工作，可以由安装流程一起完成。技能由独立版本清单和哈希发布，Bridge 报告安装版本及依赖状态；凭据、路径、字体和媒体发布配置留在本端。检测本地修改，不静默覆盖。

实现技能发布时需更新仓库交付规则，明确技能专属变更不触发 Bridge/Control Plane 程序部署。当前文件只是设计文档，不更改运行版本或部署行为。

## 实施与验收

1. 存储审计：给出现状、增长来源、数据完整度和清理预览。
2. 中央只读 MCP：完成身份认证、项目解析、搜索、回顾与原文读取；验证实际 Codex/Claude/Hermes 客户端连接。
3. 可靠采集与归档：增量补传、去重、压缩、保留和清理；验证崩溃重试、缺口报告及备份恢复。
4. 摘要和技能：低优先级整理、来源失效处理、共享技能安装与版本状态。

首个案例采用本次设计讨论：Windows 讨论已上传后进入离线状态，HAL 新会话直接通过中央 MCP 找到它，确认“中心提供 MCP、项目不持有 projectId、Obsidian 非必要、容量治理纳入设计”，并能读取消息依据。之后 Windows 能检索 HAL 新产生的讨论。

同时验证不同机器的同名目录不会误合并、并行会话不会串项目、重复补传不会增加重复正文、旧消息冷归档后仍可按指针读取、删除及摘要失效一致，以及大工具日志清理后会话完整度提示正确。测量归档前后和索引的实际空间，不以压缩率推测总体收益。
