# 0.7 控制面服务架构

状态：实施中（分支 `release/0.7`，2026-10-20）。全部完成后一起合入 main 并以 `0.7.0` 发布。

参考 go-hikaru 架构 v2：一个 Hono 应用，`/api` 给 UI 和程序，`/mcp/*` 给 agent，MCP 用官方 SDK v2 的无状态 Streamable HTTP。和 go-hikaru 不同，控制面是常驻枢纽（Bridge WebSocket、SSE、调度定时器），不做 socket activation / idle-exit。

## 1. 范围

| 项 | 0.7 做法 |
| --- | --- |
| Matrix | 整体删除：`matrix.ts`、`MATRIX_*` 配置、`matrix-js-sdk` 依赖、房间/线程启动流程、表情审批、线程输出、`log_request/log_response` 和 `start_agent/agent_input/stop_agent` 旧协议消息。数据库 `matrix_room_id/matrix_thread_id` 列保留（新会话写空），API 字段暂保留。`memory_scopes` 返回的 `matrixRooms` 是 Hermes 房间绑定，与 Matrix 网关无关，保留。 |
| HTTP 入口 | Hono 成为唯一 HTTP listener。`/api/v1`、SSE、`/control/*`、`/health`、`/memory/bootstrap`、`/mcp/*` 都在一棵路由里。`/bridge` WebSocket upgrade 仍由 `ws` 在同一 server 上处理。 |
| `/api/v1` | 契约不变。原 handler 通过 `c.env.incoming/outgoing` 挂载，请求体和 SSE 仍由原生 node 处理（SSE 依赖 `write()` 返回值做背压）。 |
| `/control/api/v1` | 不再改写 URL、注入 Bearer；改为 Hono 中间件做同源检查后直接给出 principal，复用同一批 handler。 |
| `/mcp/memory` | 对话记忆 + 记忆 + 技能，官方 SDK，短工具名。 |
| `/mcp/bridge` | 取代 abctl：驱动 worker 会话。 |
| `/mcp` | 旧 memory 端点，旧工具名，保留到 0.8。 |
| abctl | 删除 `packages/cli` 和 HAL 上的 `/usr/local/bin/abctl` 链接；Hermes 改用 `/mcp/bridge`。 |

## 2. MCP 端点

两个端点共用 `mountMcp(path, {auth, tools, instructions})`：

- Hono 中间件校验 Bearer，得到 principal，作为 `authInfo` 传给 `createMcpHandler(...).fetch`。
- 工厂按请求创建 `McpServer`，只注册该 principal 可用的工具（`tools/list` 即按权限过滤）。
- 工具表是一张 `{name, legacy?, access, description, inputSchema(JSON Schema), run}`；`inputSchema` 用 `fromJsonSchema` 交给 SDK 校验，不另写 zod。
- 结果统一 `content` + `structuredContent`，业务错误 `isError:true`。
- 客户端里的配置名决定 `mcp__<name>__<tool>` 前缀：约定 `memory` 与 `bridge`。分开两个名字，权限上 memory 可免审批，bridge 仍走审批。

### 2.1 鉴权

| 端点 | 接受的 token | 能力 |
| --- | --- | --- |
| `/mcp/memory` | conversation read token | history 只读 + memory 只读（含技能读） |
| | memory writer token | 以上 + 以该 writer 身份写记忆/技能 |
| `/mcp/bridge` | Control API read token | `workers/sessions/session/pending/wait` |
| | Control API write token | 以上 + `create/turn/approve/answer/interrupt` |

`/mcp/bridge` 复用原 abctl 的 `BridgeOps`（移入控制面），底层 `ControlClient` 以调用方的 Bearer 请求本机 loopback `/api/v1`。这样 read/write 语义、幂等和基于 SSE 的 `wait` 与 HTTP 契约完全一致。`wait` 默认 120 秒，最长 600 秒，超时返回 cursor 再等。

## 4. 无痛迁移

1. **双轨**：同一张工具表。`/mcp` 用旧名列出、调用同一 handler，旧客户端（含只发 `Accept: application/json` 的 Hermes 插件）不受影响。
2. **观测**：旧端点每次调用按 principal + 工具计数并记日志，确认谁还在用。
3. **切换调用方**：Hermes 插件（URL 与工具名）、`deploy/claude-permissions.env`、各机器 `~/.claude/settings.json` 的 `permissions.allow`（`mcp__conversation-memory` → `mcp__memory`）、MCP 客户端配置（Codex 配置交给 Codex 处理）、`shared-skills`、文档、bootstrap 注入文案。
4. **收尾**：旧端点计数归零后，0.8 删除 `/mcp` 和旧名。

## 5. 发布
