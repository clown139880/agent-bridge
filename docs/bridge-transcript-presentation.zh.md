# Bridge 对话的轮次与过程展示

Control Center 按远端 `turnId` 组织对话，保留用户输入和最后一条助手回复，
将中间消息和工具记录放入一个可展开的过程区。默认标准模式折叠已完成过程；
简洁隐藏步骤编号，详细展开过程，完全展开同时展开工具载荷。
失败、中断和未知完整性的记录默认展开。中途用户输入会断开显示分组，避免挪动消息顺序。

前端的步骤编号是展示顺序，不宣称是远端模型调用次数。一个工具的开始、进度和结束
按轮次和 itemId 合成一条记录，保留开始位置和最后结果。没有开始事件的分页片段
标注“部分记录”，没有可靠时间不显示耗时，也不推测完成状态。

## 为什么没有思考正文

目前不仅是前端没展开：适配器尚未统一保存可展示的思考文本。

- Codex app-server：reasoning item 开始时只发 `progress` / `thinking`；完成分支处理正文、命令、文件和工具，没有保存 reasoning 摘要。
- Claude：stream 的 thinking / redacted_thinking 只切换阶段；完整消息只提取 text 和 tool_use。
- Pi：thinking_start 只发阶段；消息完成提取正文。
- ACP：agent_thought_chunk 只切换阶段，没有累积它的文本。

因此现有 Bridge 事件通常只能说明“当时正在思考”，无法从中恢复思考正文。
上游是否提供可展示的摘要或文本因 agent 而异；加密或 redacted 数据不可当正文展示。
后续若增加功能，应单独定义可展示分析/摘要事件、去重与流式收敛、大小限制和历史兼容，
再分别接入两套前端。本次不改变这条采集链路。
